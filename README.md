# Граф зависимостей пакетов: вариант 17

Практическая работа № 2 по дисциплине «Конфигурационное управление».
Ветка `stage1` содержит **этап 1: минимальный прототип с конфигурацией**.

Приложение принимает настройки из командной строки, проверяет их и выводит
все шесть параметров в формате `ключ=значение`. На этом этапе приложение
не обращается к сети, не получает зависимости и не создаёт изображение.
Задание варианта 17 предусматривает NuGet, PlantUML и SVG на следующих этапах.
Готовые средства получения зависимостей не используются.

## Требования и запуск

Нужен Python 3.10 или новее. Зависимостей вне стандартной библиотеки нет.
Все команды выполняются из корня проекта.

```sh
python3 src/main.py --help
python3 src/main.py \
  --package Newtonsoft.Json \
  --repository https://api.nuget.org/v3/index.json \
  --version 13.0.3 \
  --output graph.svg \
  --filter Microsoft.
```

Ожидаемый вывод:

```text
package=Newtonsoft.Json
repository=https://api.nuget.org/v3/index.json
test_mode=False
version=13.0.3
output=graph.svg
filter=Microsoft.
```

Запуск через Makefile, если установлен `make`:

```sh
make run ARGS="--package A --repository examples/repository.txt --test-mode \
--version 1.0.0 --output graph.svg"
```

## Все настройки

| Опция | Обязательность | Проверка и назначение |
| --- | --- | --- |
| `--package` | Обязательна | Имя пакета: латинские буквы, цифры, `_`, `.`, `-`. |
| `--repository` | Обязательна | HTTP(S) URL или читаемый файл при `--test-mode`. |
| `--test-mode` | Флаг, по умолчанию выключен | Переключает URL на локальный файл. |
| `--version` | Обязательна | Версия анализируемого пакета. |
| `--output` | Обязательна | Имя будущего изображения с расширением `.svg`. |
| `--filter` | По умолчанию пустая строка | Подстрока исключаемых пакетов. |

Дополнительные правила валидации:

- Имя начинается с латинской буквы, цифры или `_`. В тестовом режиме
  используются только большие латинские буквы, например `A`, `B` или `AB`.
- Версия содержит от одного до четырёх числовых компонентов через точку.
  Допустимы суффиксы предварительной версии и метаданных, например
  `1.2.3-beta.1+build`. Проверяется синтаксис; существование пакета и версии
  в репозитории на первом этапе не проверяется.
- URL должен содержать схему `http` или `https` и имя сервера.
  Пробелы, учётные данные, фрагменты после `#` и некорректные порты запрещены.
  Доступность сервера на этом этапе не проверяется.
- Тестовый файл должен существовать, быть обычным файлом и открываться
  для чтения. Его содержимое на первом этапе не разбирается.
- Каталог изображения должен существовать. Проверяется возможность записи;
  существующий путь изображения должен быть обычным файлом.
  Существующий файл не изменяется.
- Пустой фильтр отключает фильтрацию. Строка только из пробелов недопустима.
  Сама фильтрация относится к третьему этапу.
- Управляющие символы в строковых значениях запрещены.
- Значения `--test-mode=true` и `--test-mode=false` недопустимы: для включения
  указывают флаг `--test-mode`, для выключения его опускают.
- Неизвестные опции и сокращённые имена опций не принимаются.

Относительные пути отсчитываются от текущего рабочего каталога.
В путях поддерживается `~`; вывод сохраняет исходное значение аргумента.
Значения с пробелами следует заключать в кавычки.

## Демонстрация тестового режима

```sh
python3 src/main.py \
  --package A \
  --repository examples/repository.txt \
  --test-mode \
  --version 1.0.0 \
  --output graph.svg
```

```text
package=A
repository=examples/repository.txt
test_mode=True
version=1.0.0
output=graph.svg
filter=
```

Файл `examples/repository.txt` содержит пример `A → B, C; B → C`.
Это только текстовая фикстура для проверки пути, а не реализация этапа 3.

## Демонстрация ошибок всех параметров

Ошибки выводятся в `stderr`, код завершения — `2`.
При ошибке значения конфигурации в `stdout` не выводятся.
Успешный запуск и `--help` завершаются с кодом `0`.

Следующие команды предназначены для Bash или Zsh. Общие корректные
аргументы задаются массивом; последующая опция заменяет предыдущее значение.
Каждая команда запускается отдельно и должна завершиться с ошибкой.

```sh
base=(--package Newtonsoft.Json
      --repository https://api.nuget.org/v3/index.json
      --version 13.0.3 --output graph.svg)

python3 src/main.py "${base[@]}" --package 'bad name'
python3 src/main.py "${base[@]}" --repository 'ftp://example.com'
python3 src/main.py "${base[@]}" --test-mode=maybe
python3 src/main.py "${base[@]}" --version 'latest'
python3 src/main.py "${base[@]}" --output 'graph.png'
python3 src/main.py "${base[@]}" --filter '   '
```

| Параметр | Причина ошибки в примере |
| --- | --- |
| `--package` | Пробел в имени пакета. |
| `--repository` | Неподдерживаемая схема URL. |
| `--test-mode` | Флаг не принимает значение. |
| `--version` | Вместо числовой версии указано слово. |
| `--output` | Требуется расширение `.svg`. |
| `--filter` | Фильтр состоит только из пробелов. |

Дополнительные примеры:

```sh
python3 src/main.py
python3 src/main.py "${base[@]}" --unknown
python3 src/main.py "${base[@]}" --output missing-directory/graph.svg
python3 src/main.py "${base[@]}" --package A \
  --test-mode --repository missing-repository.txt
```

Отсутствующий обязательный параметр, неизвестная опция, несуществующий
каталог изображения и отсутствующий тестовый файл также дают код `2`.

## Сборка и тесты

Отдельная сборка для запуска Python-приложения не требуется.
Проверить компиляцию и выполнить тесты можно так:

```sh
make build
make test
```

Без `make`:

```sh
python3 -m py_compile src/config.py src/main.py
python3 -m unittest discover -s tests -v
```

`make build` создаёт только локальный `__pycache__`, исключённый из Git.
Тесты запускают настоящий CLI в отдельных временных каталогах и проверяют
вывод всех настроек, значения по умолчанию, оба режима, ошибки каждого
параметра, обязательные аргументы, справку и сохранность существующего файла.
Сетевые подключения для тестирования не нужны.

## Функции исходного кода

| Функция | Назначение |
| --- | --- |
| `config.check_text(value)` | Отсеять управляющие символы. |
| `config.package_name(value)` | Проверить синтаксис имени пакета. |
| `config.package_version(value)` | Проверить синтаксис версии. |
| `config.repository_url(value)` | Проверить URL без сетевого запроса. |
| `config.repository_file(value)` | Проверить существование и чтение файла. |
| `config.output_file(value)` | Проверить путь SVG без записи в файл. |
| `config.filter_text(value)` | Проверить строковое значение фильтра. |
| `config.create_parser()` | Описать опции CLI и сформировать справку. |
| `config.validate_option(parser, name, validator, value)` | Оформить ошибку CLI. |
| `config.parse_config(argv=None)` | Прочитать и проверить все настройки. |
| `main.main(argv=None)` | Вывести конфигурацию в формате `ключ=значение`. |

У каждой функции есть docstring. Тестовые методы и их вспомогательные
функции документированы непосредственно в `tests/test_cli.py`.

## Структура и история

```text
src/config.py            Разбор и проверка параметров
src/main.py            Точка входа CLI
tests/test_cli.py        Проверки поведения CLI
examples/repository.txt  Тестовый файл
Makefile                 Запуск, проверка компиляции, тесты
.gitignore               Исключение служебных и сгенерированных файлов
README.md                Документация
```

Каждый этап выполняется в отдельной ветке и сохраняется коммитом
в формате Conventional/Scoped Commits, например `feat(stage-1): ...`.
Первый этап находится в `stage1`; этапы 2–5 здесь не реализованы.
Для защиты требуется разместить ветку в публично доступном Git-репозитории.
