# Граф зависимостей пакетов: вариант 17

Практическая работа № 2 по дисциплине «Конфигурационное управление».
Ветка `codex/stage2` реализует **этап 2: сбор данных** поверх этапа 1,
сохранённого в ветке `stage1`.

Приложение получает прямые зависимости заданной версии .NET-пакета из
NuGet-репозитория и выводит их на экран. Используется только стандартная
библиотека Python: `urllib.request`, `json`, `xml.etree.ElementTree`.
Менеджеры пакетов и сторонние библиотеки получения зависимостей не нужны.

## Требования и запуск

Нужен Python 3.10 или новее и доступ к выбранному HTTP(S) репозиторию NuGet V3.
Все команды выполняются из корня проекта.

```sh
python3 src/main.py --help
python3 src/main.py \
  --package Newtonsoft.Json \
  --repository https://api.nuget.org/v3/index.json \
  --version 13.0.3 \
  --output graph.svg
```

Запуск через Makefile:

```sh
make run ARGS="--package Newtonsoft.Json \
--repository https://api.nuget.org/v3/index.json \
--version 13.0.3 --output graph.svg"
```

## Получение и формат данных

1. Прочитать JSON-индекс по пользовательскому `--repository`.
2. Найти адрес ресурса `PackageBaseAddress/3.0.0` в `resources`.
3. Привести имя пакета к нижнему регистру, нормализовать версию.
4. Загрузить `{base}/{package}/{version}/{package}.nuspec`.
5. Разобрать XML и вывести элементы `metadata/dependencies/dependency`
   и `metadata/dependencies/group/dependency`.

Обращение выполняется именно к указанной версии: автоматического выбора
последней версии нет. Числовые компоненты версии приводятся к числам,
недостающие компоненты дополняются до трёх; четвёртый нулевой компонент
удаляется. Метаданные после `+` исключаются из URL, суффикс предварительной
версии переводится в нижний регистр. Например, `01.2.003.0+build` → `1.2.3`.

Каждая строка содержит три поля, разделённые табуляцией:

```text
имя пакета    ограничение версии    целевая платформа
```

Заголовок таблицы не печатается. Сохраняются ограничения версий из манифеста,
например `[1.0,2.0)`. При отсутствии ограничения выводится `любая версия`,
при отсутствии платформы — `без указания платформы`.

Выводятся зависимости всех групп платформ: настройка выбора платформы
в задании отсутствует. Один пакет может встречаться в нескольких строках
с разными платформами и ограничениями. Пустые группы не создают строк.
Если зависимостей нет, выводится `Прямых зависимостей нет.`
Порядок строк соответствует порядку элементов в манифесте.

Использован протокол из официальной документации:
[NuGet Package Content API](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource),
[формат .nuspec](https://learn.microsoft.com/en-us/nuget/reference/nuspec).

## Примеры использования

Пакет с зависимостями:

```sh
python3 src/main.py --package Newtonsoft.Json --version 13.0.3 \
  --repository https://api.nuget.org/v3/index.json --output graph.svg
```

Среди строк для этой версии есть:

```text
Microsoft.CSharp	4.3.0	.NETStandard1.0
NETStandard.Library	1.6.1	.NETStandard1.0
```

Пакет без прямых зависимостей:

```sh
python3 src/main.py --package jQuery --version 3.7.1 \
  --repository https://api.nuget.org/v3/index.json --output graph.svg
```

```text
Прямых зависимостей нет.
```

Отсутствующий пакет или версия:

```sh
python3 src/main.py --package Newtonsoft.Json --version 9999.0.0 \
  --repository https://api.nuget.org/v3/index.json --output graph.svg
```

Ожидается ошибка `HTTP 404` в `stderr` и код завершения `2`.
Точные сообщения других сетевых ошибок зависят от сервера и окружения.

## Все настройки

| Опция | Обязательность | Назначение |
| --- | --- | --- |
| `--package` | Обязательна | Имя анализируемого NuGet-пакета. |
| `--repository` | Обязательна | HTTP(S) URL JSON-индекса NuGet V3. |
| `--version` | Обязательна | Конкретная версия пакета. |
| `--output` | Обязательна | Путь будущего SVG, проверяется без записи. |
| `--filter` | По умолчанию `""` | Подстрока фильтрации для этапа 3. |
| `--test-mode` | Флаг, по умолчанию выключен | Тестовый режим для этапа 3. |

Сохранена валидация параметров из этапа 1:

- Имя начинается с латинской буквы, цифры или `_`; далее допустимы также
  `.` и `-`. В тестовом режиме разрешены только большие латинские буквы.
- Версия содержит от одного до четырёх числовых компонентов через точку.
  Допустимы суффиксы, например `1.2.3-beta.1+build`.
- URL должен содержать схему `http` или `https` и имя сервера.
  Пробелы, учётные данные, фрагменты и некорректные порты запрещены.
- При `--test-mode` проверяются существование и читаемость локального файла.
  После проверки аргументов приложение сообщает, что этот режим относится
  к этапу 3, и завершается с кодом `2`; содержимое файла не разбирается.
- Выходной путь должен иметь расширение `.svg` и существующий доступный
  для записи родительский каталог. Существующий файл не изменяется.
- Пустой фильтр допустим; строка только из пробелов запрещена.
- Управляющие символы запрещены. Неизвестные и сокращённые опции отвергаются.
- Флаг `--test-mode` не принимает значений `true` или `false`.

Относительные пути отсчитываются от текущего рабочего каталога;
поддерживается `~`. Значения с пробелами заключают в кавычки.

На этапе 2 `--filter` не исключает зависимости, `--output` не создаёт
изображение. Обход транзитивных зависимостей, DFS, обработка циклов, разбор
тестового графа, порядок загрузки, PlantUML и SVG относятся к этапам 3–5.
Вывод конфигурации `ключ=значение` требовался только на этапе 1 и заменён
выводом прямых зависимостей.

## Обработка ошибок

Успешный запуск и `--help` возвращают `0`. Ошибки аргументов и получения
данных возвращают `2`; сообщение идёт в `stderr`, `stdout` остаётся пустым.
Обрабатываются HTTP-ошибки, отсутствие пакета/версии, недоступность сети,
тайм-аут, неверный JSON, отсутствие `PackageBaseAddress`, неверный адрес
ресурса, некорректный XML и отсутствие обязательной структуры манифеста.
Тайм-аут каждой сетевой операции — 20 секунд.

Если Python сообщает `CERTIFICATE_VERIFY_FAILED`, нужно настроить доверенные
корневые сертификаты в используемом Python или переменную `SSL_CERT_FILE`.
Приложение использует стандартную проверку TLS-сертификата.

Примеры ошибок аргументов для Bash/Zsh:

```sh
base=(--package Newtonsoft.Json
      --repository https://api.nuget.org/v3/index.json
      --version 13.0.3 --output graph.svg)
python3 src/main.py "${base[@]}" --package 'bad name'
python3 src/main.py "${base[@]}" --repository 'ftp://example.com'
python3 src/main.py "${base[@]}" --test-mode=maybe
python3 src/main.py "${base[@]}" --version latest
python3 src/main.py "${base[@]}" --output graph.png
python3 src/main.py "${base[@]}" --filter '   '
```

## Сборка и тесты

```sh
make build
make test
```

Без `make`:

```sh
python3 -m py_compile src/config.py src/nuget.py src/main.py
python3 -m unittest discover -s tests -v
```

Отдельная сборка для запуска не требуется. Создаваемый `__pycache__`
исключён из Git. Тесты не обращаются к внешним репозиториям: для проверки
реального CLI используется HTTP-сервер на `127.0.0.1` со случайным портом.
Окружение должно разрешать локальные сокеты.

Проверяются валидация всех опций, нормализация версии, получение адреса
из индекса, запрос только нужной версии, прямые зависимости без обхода,
группы платформ, диапазоны версий, отсутствие зависимостей, сетевые ошибки,
повреждённые ответы, отсутствие фильтрации и сохранность выходного файла.

## Функции исходного кода

| Функция | Назначение |
| --- | --- |
| `config.check_text(value)` | Отсеять управляющие символы. |
| `config.package_name(value)` | Проверить синтаксис имени пакета. |
| `config.package_version(value)` | Проверить синтаксис версии. |
| `config.repository_url(value)` | Проверить HTTP(S) URL без запроса. |
| `config.repository_file(value)` | Проверить существование и чтение файла. |
| `config.output_file(value)` | Проверить путь SVG без записи. |
| `config.filter_text(value)` | Проверить значение фильтра. |
| `config.create_parser()` | Описать опции CLI и справку. |
| `config.validate_option(parser, name, validator, value)` | Оформить ошибку CLI. |
| `config.parse_config(argv=None)` | Прочитать и проверить настройки. |
| `nuget.normalized_version(value)` | Нормализовать версию для NuGet URL. |
| `nuget.fetch_bytes(url)` | Прочитать HTTP-ответ с обработкой ошибок. |
| `nuget.package_base_address(repository)` | Найти ресурс в индексе NuGet V3. |
| `nuget.read_dependency(element, framework)` | Прочитать одну зависимость. |
| `nuget.parse_nuspec(content)` | Извлечь прямые зависимости из XML. |
| `nuget.get_dependencies(repository, package, version)` | Получить зависимости версии. |
| `nuget.format_dependency(dependency)` | Подготовить строку вывода. |
| `main.main(argv=None)` | Выполнить запрос и вернуть код завершения. |

`nuget.Dependency` — неизменяемая запись имени, ограничения версии и платформы.
`nuget.RepositoryError` — ошибка получения или разбора данных репозитория.
У всех функций и классов есть docstring. Тестовые методы и вспомогательный
HTTP-сервер документированы непосредственно в папке `tests`.
