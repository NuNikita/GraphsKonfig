# Граф зависимостей пакетов: вариант 17

Практическая работа № 2, **этап 2: сбор данных**, ветка `stage2`.
Приложение получает прямые зависимости указанной версии NuGet-пакета
и выводит их на экран. Используется только стандартная библиотека Python;
менеджеры пакетов и сторонние библиотеки получения зависимостей не нужны.

## Запуск

Нужен Python 3.10+ и доступ к NuGet V3. Команды выполняются из корня проекта.

```sh
python3 src/main.py \
  --package Newtonsoft.Json \
  --repository https://api.nuget.org/v3/index.json \
  --version 13.0.3 \
  --output graph.svg
```

Программа находит `PackageBaseAddress/3.0.0` в индексе репозитория,
нормализует версию и загружает `.nuspec` только выбранного пакета.
Каждая строка вывода: имя зависимости, ограничение версии и платформа,
разделённые табуляцией. Например:

```text
Microsoft.CSharp    4.3.0    .NETStandard1.0
NETStandard.Library 1.6.1    .NETStandard1.0
```

Выводятся все группы платформ, поэтому имена могут повторяться.
При отсутствии зависимостей выводится `Прямых зависимостей нет.`

Другие примеры:

```sh
# Пакет без прямых зависимостей
python3 src/main.py --package jQuery --version 3.7.1 \
  --repository https://api.nuget.org/v3/index.json --output graph.svg

# Несуществующая версия: ошибка HTTP 404
python3 src/main.py --package Newtonsoft.Json --version 9999.0.0 \
  --repository https://api.nuget.org/v3/index.json --output graph.svg

# Справка
python3 src/main.py --help
```

## Параметры

| Опция | Назначение |
| --- | --- |
| `--package` | Обязательное имя пакета: латинские буквы, цифры, `_`, `.`, `-`. |
| `--repository` | Обязательный HTTP(S) URL индекса NuGet V3. |
| `--version` | Обязательная версия: 1–4 числовых компонента, возможны суффиксы. |
| `--output` | Обязательный путь `.svg` в существующем доступном для записи каталоге. |
| `--filter` | Подстрока фильтрации, по умолчанию пустая; применяется на этапе 3. |
| `--test-mode` | Флаг тестового режима для этапа 3; сейчас завершается с пояснением и кодом `2`. |

Сохранена проверка параметров этапа 1: запрещены управляющие символы,
неверные URL и неизвестные опции. В тестовом режиме проверяются читаемость
файла репозитория и имя пакета из больших латинских букв.
Относительные пути отсчитываются от текущего каталога; поддерживается `~`.

На этапе 2 фильтрация и обход графа не выполняются, SVG не создаётся.

## Ошибки и тесты

Успешный запуск возвращает `0`, ошибка — `2` с сообщением в `stderr`.
Обрабатываются ошибки аргументов, HTTP, соединения, JSON и XML;
тайм-аут сетевой операции — 20 секунд.

```sh
make build  # Проверка компиляции
make test   # Все тесты
```

Без `make`:

```sh
python3 -m py_compile src/config.py src/nuget.py src/main.py
python3 -m unittest discover -s tests -v
```

Тесты проверяют параметры, разбор манифестов, запрос нужной версии и ошибки.
Они используют локальный HTTP-сервер; доступ к внешней сети не нужен.

## Функции

| Модуль | Функции и назначение |
| --- | --- |
| `src/config.py` | `check_text` — управляющие символы; `package_name` — имя; `package_version` — версия. |
| | `repository_url` — URL; `repository_file` — читаемость файла; `output_file` — путь SVG; `filter_text` — фильтр. |
| | `create_parser` — опции CLI; `validate_option` — ошибки валидации; `parse_config` — чтение и проверка настроек. |
| `src/nuget.py` | `normalized_version` — нормализация версии; `fetch_bytes` — HTTP-запрос. |
| | `package_base_address` — поиск адреса ресурса; `get_dependencies` — получение манифеста версии. |
| | `read_dependency` — одна зависимость; `parse_nuspec` — зависимости из XML. |
| | `format_dependency` — строка вывода; `Dependency` — запись зависимости; `RepositoryError` — ошибка репозитория. |
| `src/main.py` | `main` — запуск, вывод результата и код завершения. |

Тесты находятся в `tests/`, фикстура будущего тестового режима —
в `examples/repository.txt`. Функции и классы документированы через docstring.
